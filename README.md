# StackPort

StackPort는 로컬 우선 원격 접속·데이터베이스 작업 공간을 만드는 프로젝트입니다. 전체 요구사항은 [기능 명세서](StackPort_Functional_Spec_KO.md)에 있습니다. 현재 코드는 초기 구현이며 명세 전체가 완성된 제품이 아닙니다.

## 현재 사용 가능한 기능

- 프로젝트 탐색기를 유지한 채 상단에서 데이터베이스·터미널·파일 탐색·원격 화면·네트워크 전환
- **화면 설정**에서 라이트·다크·시스템 테마를 선택하고 앱을 다시 열어도 같은 설정 유지
- 컴팩트 보기로 목록 간격을 줄이고, 집중 모드로 현재 분할 작업을 유지하며 탐색기와 도구 표시줄 숨기기
- 연결마다 여러 SQL 탭을 열고, UTF-8 파일을 새 탭에 불러오거나 새 `.sql` 파일로 저장
- 미저장 SQL 탭을 닫거나 앱을 종료할 때 필요한 초안만 파일로 저장
- `Ctrl+Shift+P` 명령 팔레트로 도구·프로젝트·현재 프로젝트의 연결·현재 SQLite 연결의 테이블과 뷰 열기
- 최대 네 작업 도구를 2×2 또는 영역별 좌우·상하 분할로 배치하고 마우스나 방향키로 크기 조절
- 앱을 다시 열 때 마지막 프로젝트·SQLite 연결·분할 배치·탐색기 상태 복원
- SQLite 테이블과 뷰를 데이터 그리드에서 바로 열고, 접을 수 있는 SQL 편집기에서 작성 중인 쿼리 유지
- SQL 편집기에서 선택한 부분의 실행 계획을 보거나, 선택한 부분 또는 커서가 속한 문장 실행
- SQLite SQL 편집기에서 문서 전체 또는 선택 영역의 여러 문장을 실행하고 문장마다 결과·실행 시간·내보내기 확인
- SQL 탭마다 조회 페이지 고정, 같은 페이지의 값 비교, 저장한 쿼리와 매개변수로 재실행
- 문서 또는 선택한 SQL을 프로젝트 템플릿으로 저장하고, 폴더·즐겨찾기·검색으로 찾아 새 SQL 탭에서 열기
- SQLite 연결별 최근 SQL에서 실행 범위·결과·소요 시간을 확인하고 SQL을 새 탭에서 열기
- SQLite 쿼리 빌더에서 테이블·뷰를 선택하거나 관계 영역으로 드래그해 조인, 조회 열, 조건 및 집계 구성
- SQLite 관계도에서 기본 키·외래 키와 연결된 테이블을 탐색하고 테이블 구조로 바로 이동
- 관계도나 명령 팔레트에서 SQLite의 선택한 객체 또는 전체 테이블·뷰를 Markdown·HTML 데이터 사전으로 저장
- 두 SQLite 연결에서 열·키·인덱스·트리거·정의 SQL을 비교하고 생성·삭제·뷰 재정의 초안 검토
- SQLite의 새 일반 테이블·뷰와 출력 열이 같은 뷰 재정의를 선택해 검토하고, 대상 사전 백업 후 적용 결과 확인
- SQLite SQL 편집기에서 `Ctrl+Space`로 현재 연결의 스키마·테이블·뷰·열·함수·키워드 후보 열기, 별칭 뒤 `.`로 열 후보 열기
- SQLite SQL 편집기에서 입력 중 문법·객체 참조·읽기 전용 정책 검사, 진단 목록에서 오류 위치로 이동
- SQLite SQL 편집기에서 `F12`로 테이블·뷰·열 정의 확인, 생성 SQL과 현재 문장에서 확인한 참조로 이동
- SQLite SQL 편집기에서 객체 이름에 마우스를 올려 열 형식이나 테이블·뷰 정보를 확인하고 정의 열기
- SQLite SQL 편집기에서 `F2`로 테이블 별칭의 선언과 참조를 함께 변경, 위치 미리보기 및 적용 전 SQLite 검증
- SQLite SQL 편집기에서 `Ctrl+Alt+F`로 문서 전체 또는 선택 영역의 서식과 축약 결과 미리보기, 들여쓰기·키워드 대소문자·문장 사이 빈 줄 설정 저장
- SQL 탭을 오가며 각 탭의 마지막 결과 페이지와 실행 계획 확인
- SQL과 SFTP 텍스트 편집기에서 줄 번호와 커서 위치 확인, SQLite SQL 및 원격 `.sql`·`.json`·`.xml` 파일 구문 강조
- SQL과 SFTP 편집기에서 일반 텍스트를 찾고 한 건씩 또는 한 번에 바꾸기
- 터미널 상단에서 PowerShell·CMD 탭을 바로 열고, SSH는 직접 입력하거나 탐색기의 저장된 연결로 시작
- 터미널 탭을 끌거나 `Alt+←/→`로 순서를 바꾸고, 탭 관리에서 자주 쓰는 탭 고정
- 터미널 탭 복제, 최근 닫은 탭 다시 열기, 확인 후 고정하지 않은 탭 일괄 닫기
- 각 터미널의 메모리 스크롤백에서 일반 문자열을 앞뒤로 검색하고 대소문자 구분
- 현재 터미널 탭의 스크롤백과 화면을 TXT 또는 ANSI 파일로 저장
- Windows 원격 데스크톱 (RDP)의 기본 연결과 화면·리디렉션 세부 설정, 별도 목록에서 열린 클라이언트 관리
- 저장된 SSH 연결로 SFTP를 열어 로컬·원격 파일을 두 창에서 탐색하고, 좁은 창에서는 현재 경로를 유지한 채 전환
- 로컬과 원격 목록에서 파일 이름을 검색하고 이름·크기·수정 시각으로 각각 정렬
- 각 파일 창에서 방문한 폴더로 뒤로·앞으로 이동하고 `Ctrl+L`로 경로 입력
- 로컬·원격 폴더 및 선택한 하위 폴더 구조의 유형·크기·수정 시각 비교, 파일 쌍의 SHA-256·UTF-8 줄·바이너리 바이트 차이 확인
- 현재 로컬·원격 폴더에서 이름이 다른 파일도 직접 선택해 비교
- 원격 파일·폴더 목록에서 Unix 권한과 소유자·그룹 ID 변경
- 동기화 방향과 제외 패턴을 적용해 파일 복사·갱신·삭제 후보를 미리 확인
- 확인한 동기화 계획의 새 폴더·파일과 SHA-256 검증을 마친 기존 파일 갱신 실행, 항목별 결과와 작업 기록 확인
- 단방향 동기화의 삭제 후보 검증과 명시적 확인, 변경된 파일과 비어 있지 않은 폴더 보존
- UTF-8 파일의 변경 구간별 내용을 선택해 병합하고 새 로컬 파일로 저장
- 현재 SFTP 경로에 새 폴더를 만들고 목록 갱신
- 원격 파일이나 폴더의 이름을 같은 SFTP 폴더 안에서 변경
- 같은 SFTP 연결에서 대상 경로를 확인한 뒤 파일이나 폴더 이동
- 같은 SFTP 연결에서 일반 파일을 복사하고 원격 복사본의 SHA-256 확인
- SFTP에서 원격 파일 또는 빈 폴더 한 개의 삭제 대상을 확인하고 삭제
- 로컬·SFTP 파일의 UTF-8 원문, 바이너리 HEX와 정적 PNG 미리보기
- SFTP UTF-8 파일을 편집하고 원본 해시를 확인해 저장하거나 새 이름으로 저장
- 미저장 SFTP 편집 내용을 새 로컬 텍스트 파일에 보관하고, 편집기를 닫거나 앱을 종료하기 전에 처리 방법 선택
- 원격 파일을 새 로컬 경로에 다운로드하고 진행률·속도·남은 시간과 SHA-256 확인
- 로컬 파일을 현재 SFTP 폴더에 올리고, 원격에 기록된 내용을 SHA-256으로 확인한 뒤 새 이름으로 게시
- 작업 기록에서 SFTP 전송·편집·권한 변경·파일 관리·동기화의 결과 및 대상 연결 확인
- Windows OpenSSH를 이용한 SSH 터미널과 호스트 키 지문 확인·고정·명시적 교체
- SSH 세션에서 개인 키 또는 에이전트에 등록된 공개 키 파일을 직접 선택
- SSH 연결 화면에서 DNS 조회와 TCP 포트 연결을 단계별로 진단
- Windows 로컬 TCP·UDP 포트를 IPv4·IPv6와 프로세스별로 조회·필터링
- 네트워크 화면에서 DNS·TCP, Ping, 경로 추적과 HTTP/HTTPS 상태를 확인하고, 다른 도구에 다녀와도 결과 유지
- 로컬 프로젝트 생성·이름 변경·복제·보관·재활성화·삭제와 프로젝트별 SQLite·SSH 연결 정의 저장
- 선택한 SSH 연결을 버전형 JSON으로 내보내고, 내용을 확인한 뒤 원하는 연결만 가져오기
- 기존 SQLite 파일에서 테이블과 뷰, 열·키·인덱스·생성 SQL을 읽기 전용으로 탐색
- 테이블과 뷰의 조건 필터, 다중 열 정렬, NULL 순서 설정 및 조회 SQL 확인
- 읽기 전용 SQL 실행, 결과 100행씩 조회, NULL과 BLOB 구분 표시
- 필터·정렬 또는 SQL 매개변수가 적용된 전체 결과를 CSV·JSON으로 내보내고 진행 행 수 확인·중단
- 실행 중인 SQLite 조회 중단과 시간 초과 표시, 중단 후 다시 조회
- SQL 매개변수를 감지해 텍스트·정수·실수·NULL·BLOB 값으로 바인딩
- SQLite 실행 계획을 단계별로 보고 인덱스 검색·스캔·임시 정렬 확인
- SQLite 결과 페이지별 조회 시간, 읽은 행, 전체 스캔 단계와 정렬 횟수를 보고 같은 페이지의 고정 결과와 비교
- 지원되는 SQLite 테이블의 단일 셀을 미리보기·명시적 승인 후 변경하고 행 전체의 동시 수정과 저장 결과 검증
- 연결별 SQL 초안을 앱 실행 중 메모리에 보관하고, 프로젝트·연결 삭제 전 영향 확인
- SQLite 온라인 백업 API로 전체 DB 스냅샷을 만들고 무결성 검사. 기존 파일은 덮어쓰지 않음
- SQLite 백업의 대상·객체 수·행 수·SHA-256을 미리보고 새 파일로 복원해 검증
- 프로젝트·연결 변경, SQLite 셀 변경·백업·복원·결과 내보내기의 로컬 작업 기록 조회

삭제 명령은 저장된 연결 정의만 삭제하며 데이터베이스 파일을 삭제하지 않습니다. 파일은 미리 존재해야 합니다. SQL 편집기는 결과를 반환하는 읽기 전용 문장을 실행합니다. SQL 쓰기, DDL, PRAGMA 및 데이터베이스 첨부는 지원하지 않습니다. `SELECT :value`처럼 매개변수가 있는 문장 하나를 실행하면 형식과 값을 입력하는 창이 열립니다. 입력한 값은 현재 조회와 페이지 이동에 사용합니다. 조회에는 10초 시간 제한을 적용하며 중단이 확인된 뒤 결과를 표시합니다. SQLite가 긴 개별 작업이나 파일 잠금을 처리하는 동안에는 중단 확인이 지연될 수 있습니다. 셀의 긴 텍스트는 앞 4,096자만 표시합니다. 그리드의 필터와 정렬은 페이지 이동 중 유지되며 앱에 저장하지 않습니다. 직접 작성한 SQL의 결과 순서가 중요하면 `ORDER BY`를 지정하세요. 쿼리 초안은 앱 종료나 비정상 종료 후 복구되지 않습니다.

`Ctrl+Enter`는 선택 영역이나 문서 전체를 실행하고, `Ctrl+Alt+Enter`는 문서 전체를 실행합니다. 여러 문장은 같은 연결에서 최대 16개, UTF-8 256 KiB까지 10초 안에 순서대로 실행합니다. 오류, 중단, 시간 초과, 결과 크기 한도 또는 매개변수가 있는 문장을 만나면 해당 위치에서 멈추고 앞선 결과를 유지합니다. 매개변수가 있는 문장은 `Ctrl+Shift+Enter`로 개별 실행할 수 있습니다.

**현재 페이지 고정**은 보이는 조회 페이지를 SQL 탭에 최대 8개 보관합니다. 같은 페이지를 행·열 순서로 비교하며 BLOB과 잘린 값은 일치 여부가 불명확하면 별도로 표시합니다. **고정 쿼리 재실행**으로 같은 페이지의 새 현재 결과를 열어 페이지를 이동하거나 내보낼 수 있습니다. 고정 결과와 매개변수는 탭을 닫거나 앱을 종료하면 사라집니다.

**SQL 템플릿**은 프로젝트의 로컬 작업 공간에 SQL 본문을 저장합니다. 같은 프로젝트의 SQLite 연결에서 새 초안으로 열 수 있습니다. `:value` 같은 매개변수의 실제 값은 실행할 때 입력합니다. 프로젝트를 복제하면 템플릿 사본도 생성됩니다.

**최근 SQL**은 실행이 끝난 SQL을 연결별 최대 30건까지 세션 메모리에 보관합니다. 전체 SQL 보관량에 도달하면 오래된 기록부터 제거되며, 긴 SQL은 가린 미리보기와 실행 정보를 보관합니다. **SQL 원문 표시**로 보관된 문장을 확인하고, 새 탭에서 다시 실행할 때 매개변수 값을 입력할 수 있습니다. 기록은 연결별로 지울 수 있고 앱을 종료하면 사라집니다.

**쿼리 빌더**는 현재 SQLite 연결의 테이블과 뷰로 읽기 전용 조회를 구성합니다. 최대 8개 객체를 추가하고 INNER·LEFT JOIN과 외래 키를 선택하거나 관계 열을 직접 지정할 수 있습니다. 조회 열·집계, WHERE, GROUP BY와 HAVING, ORDER BY, LIMIT를 구성한 뒤 생성된 SQL을 새 탭에서 검토합니다. 조건의 매개변수 값은 실행할 때 입력합니다.

행 편집은 원본 SQLite 파일을 실제로 변경합니다. 기본 키가 있고 트리거·생성 열이 없는 일반 테이블에서 기본 키·고유 키가 아닌 짧은 텍스트, 정수, 실수 또는 NULL 셀 하나를 변경할 수 있습니다. BLOB, 긴 값, NULL/BLOB 기본 키와 가상 테이블은 편집할 수 없습니다. 미리보기 이후 행이 바뀌거나 제약·형식 검증이 실패하면 변경을 중단합니다. `PROD` 연결은 `PROD`를 직접 입력해야 합니다. 저장 후 자동 되돌리기는 없으므로 필요하면 먼저 백업하세요.

백업 및 복원 파일은 암호화되지 않으므로 저장 폴더의 권한으로 보호하세요. 백업 생성 뒤 탐색기의 **SQLite 백업 복원**에서 독립된 SQLite 백업을 선택하고 새 파일로 복원할 수 있습니다. 복원본을 별도로 열어 검사한 뒤 백업과 SHA-256이 일치할 때만 저장합니다. 예약, 암호화, 기존 데이터베이스 덮어쓰기와 자동 복원은 아직 제공하지 않습니다.

로컬 터미널은 Windows 10 1809 이상의 ConPTY가 필요합니다. PowerShell은 프로필을 불러오지 않고, CMD는 자동 실행 설정 없이 시작합니다. 터미널 출력은 메모리에 유지하고 `출력 저장`을 선택한 경우에만 파일에 씁니다. 셸과 실행한 프로그램은 자체 기록 설정을 사용합니다. 여러 줄 붙여넣기와 터미널·앱 종료 시 확인하며, 터미널 종료 시 연결된 프로세스도 종료될 수 있습니다.

터미널의 `출력 찾기` 또는 `Ctrl+Shift+F`로 현재 탭의 화면과 메모리 스크롤백을 검색할 수 있습니다. 검색어는 탭에만 임시 보관하며 검색을 닫으면 지웁니다. 정규식과 디스크에 저장된 과거 출력 검색은 아직 제공하지 않습니다.

SSH 터미널은 Windows에 설치된 OpenSSH를 사용합니다. 처음 조회한 지문은 인증되지 않은 값이므로 서버 관리자에게 받은 값과 별도의 경로로 비교한 뒤 신뢰해야 합니다. 이후 저장된 키와 다른 서버는 차단되며, 키를 교체하려면 새 지문을 다시 확인하고 직접 승인해야 합니다. 프로젝트에 이름·호스트·포트·사용자와 환경을 저장할 수 있으며 저장된 `PROD` 연결은 열기 전에 `PROD`를 직접 입력해야 합니다. 직접 입력하는 임시 연결은 환경이 지정되지 않으므로 이 확인이 적용되지 않습니다. 연결 정의를 삭제해도 열린 세션과 호스트 키 신뢰 기록은 유지됩니다. 세션별로 자동, 지정한 키 파일(최대 8개), 암호 또는 서버 대화형 인증을 선택할 수 있습니다. 대화형 로그인에서는 서버의 안내와 확인 코드 질문에 터미널에서 답합니다. 키 파일 경로와 인증 응답은 저장하지 않습니다. 키 경로에 `%` 또는 `${...}`는 사용할 수 없습니다. 점프 호스트·터널과 다른 OS의 SSH 터미널 지원은 아직 없습니다.

`파일 탐색`에서 현재 프로젝트의 저장된 SSH 연결로 SFTP를 열 수 있습니다. SSH 터미널에서 확인한 서버 키를 공유하며, SFTP 연결에도 사용자 암호 또는 개인 키가 필요합니다. 로컬과 원격의 폴더 이동·새로고침과 원격 파일 크기, 수정 시각, 소유자·그룹 ID, 권한을 확인할 수 있습니다.

파일 미리보기는 전체를 읽은 UTF-8 JSON을 들여쓰기로, XML을 요소와 속성으로, 쉼표 구분 CSV를 표로 표시합니다. `원문`으로 전환할 수 있으며 형식 오류, 미리보기 크기 한도, XML의 DTD 또는 처리 지시문이 있으면 원문이 표시됩니다. CSV 표에는 처음 100행과 32열까지 표시합니다.

파일 창의 `터미널 경로 따라가기`를 켜면 활성 터미널의 폴더가 바뀔 때 파일 목록을 갱신합니다. 로컬 창은 Windows PowerShell의 드라이브 경로를 지원합니다. 원격 창은 같은 저장된 SSH 연결을 쓴 활성 터미널에서 셸이 `OSC 7`로 경로를 보고할 때 동작합니다.

동기화 계획의 `프로필로 저장`은 두 폴더, 방향, 하위 폴더 포함 여부, 제외 패턴과 삭제 후보 옵션을 작업 공간에 보관합니다. 같은 SSH 연결의 `동기화 프로필`에서 `계획 새로 만들기`를 누르면 현재 파일을 다시 읽습니다. 원격 변경과 삭제에는 계획 검토 및 각 확인 절차가 적용됩니다. SSH 연결 설정이 바뀌면 현재 연결에서 새 프로필을 저장해야 합니다.

원격 텍스트 편집 중 `로컬에 초안 저장`을 선택하면 변경 내용을 새 `.txt` 파일에 보관할 수 있습니다. 원격 원본은 그대로이며, 로컬 파일에 저장한 뒤 편집을 이어가거나 열린 편집기 또는 앱을 닫을 수 있습니다.

`외부 편집기`에서 Windows 편집기의 `.exe`를 선택하면 현재 내용을 임시 `.txt` 파일로 엽니다. 외부 편집기에서 파일을 저장하고 닫은 뒤 `변경 가져오기`를 누르세요. 가져온 내용을 검토하고 `저장`을 눌러 원격에 반영할 수 있습니다. 임시 파일은 가져오거나 삭제를 확인하면 정리됩니다.

SSH 연결 화면의 DNS·TCP 진단은 서버에 짧은 TCP 연결을 시도하고 곧바로 닫습니다. SSH 호스트 키, 로그인 및 서버 권한은 검사하지 않으며 서버에 연결 기록이 남을 수 있습니다.

SSH 연결 가져오기·내보내기는 이름, 호스트, 포트, 사용자와 환경만 포함하며 암호·개인 키·호스트 키 신뢰 기록은 포함하지 않습니다. 파일에는 서버와 사용자 정보가 있으므로 공유 대상을 확인하세요. 가져올 내용은 미리 확인하고 선택해야 하며 같은 이름도 별도 연결로 추가됩니다. 파일 형식과 제한은 [구현 현황](docs/IMPLEMENTATION.md#ssh-연결-교환-형식)을 참고하세요.

다른 DB 엔진, 행 추가·삭제와 일괄 편집, 협업, AI, 브라우저 게이트웨이 및 설치·업데이트 패키지 등 나머지 기능은 아직 제공되지 않습니다. 브라우저에서는 로컬 파일 연결과 터미널을 제공하지 않습니다. 요구사항별 현재 상태는 [추적표](docs/requirements.csv), 구현 경계와 검증 범위는 [구현 현황](docs/IMPLEMENTATION.md)을 참고하세요.

## 개발 실행

Windows에서 Node.js 20.19 이상 또는 22.12 이상, Rust, C++ 빌드 도구, WebView2가 필요합니다. macOS와 Linux는 아직 검증하지 않았습니다.

```powershell
npm ci
npm run dev
```

다른 터미널에서 다음을 실행합니다.

```powershell
cargo run --manifest-path src-tauri/Cargo.toml
```

프런트엔드를 빌드하고 내장 리소스로 데스크톱 바이너리를 만들려면 다음을 실행합니다. 서명된 배포 패키지는 아직 구성하지 않았습니다.

```powershell
npm run build
cargo build --release --features custom-protocol --manifest-path src-tauri/Cargo.toml
```

메타데이터는 기본적으로 OS의 앱 데이터 디렉터리에 있는 `workspace.sqlite`에 저장됩니다. 별도의 위치를 사용하려면 실행 전에 `STACKPORT_DATA_DIR` 환경 변수를 지정할 수 있습니다. 스키마 1~3의 작업 공간은 스키마 4로 이관하기 전에 같은 폴더에 무결성을 확인한 백업을 남깁니다. 스키마 4를 지원하는 앱에서 이관된 작업 공간을 열 수 있습니다. 연결 정의와 작업 기록이 포함된 폴더와 백업의 접근 권한은 사용자가 관리해야 합니다. 비밀번호나 개인키를 저장하는 기능은 없습니다.

Windows EXE를 **휴대형 작업 공간**으로 사용하려면 쓰기 가능한 폴더에 놓고 `StackPort-Windows-x64.exe --portable`로 실행하거나, 같은 폴더에 빈 `StackPort.portable` 파일을 만든 뒤 EXE를 실행하세요. 작업 공간, SSH 호스트 키 기록 및 기본 WebView 프로필은 EXE 옆 `StackPort-data` 폴더를 사용합니다. 앱 상단에 모드와 빌드 버전이 표시됩니다. WebView2 Runtime이 필요하며, 휴대형 실행에서도 자동 업데이트와 플러그인 설치는 제공하지 않습니다. 기존 작업 공간을 자동으로 가져오지 않습니다.

기존 작업 공간을 옮길 때는 탐색기의 **데이터 복사**에서 새 폴더를 선택하고 복사할 파일을 확인하세요. 검증된 복사본은 다음 실행에서 `STACKPORT_DATA_DIR`로 지정하거나 휴대형 실행의 `StackPort-data` 폴더로 사용할 수 있습니다. 연결이 참조하는 SQLite 원본 파일은 별도로 관리합니다.

```powershell
cargo test --manifest-path crates/stackport-core/Cargo.toml
npm run build
cargo check --manifest-path src-tauri/Cargo.toml
```

## Windows 자동 릴리즈

`main`에 커밋을 푸시하거나 GitHub의 **Actions → Windows build and release → Run workflow**를 실행하면 Windows x64 EXE를 빌드하고 GitHub Release를 하나 만듭니다. 빌드와 테스트가 성공해야 릴리즈가 게시됩니다. 실행 결과의 Actions 산출물과 릴리즈에는 `StackPort-Windows-x64.exe` 및 `SHA256SUMS.txt`가 포함됩니다. EXE에는 WebView2 Runtime이 필요하며 현재 코드 서명은 제공하지 않습니다.

버전은 `vMAJOR.MINOR.PATCH` 형식입니다. 첫 릴리즈는 소스의 기준 버전으로 시작합니다. 이후 `feat:` 또는 `feat(범위):` 커밋은 MINOR, `BREAKING CHANGE:` 또는 `!`가 붙은 Conventional Commit은 MAJOR를 올립니다. 그 밖의 변경이나 새 커밋이 없는 수동 실행은 PATCH를 올립니다. 수동 실행 시 `bump`를 `patch`, `minor`, `major`로 직접 선택할 수도 있습니다. 동시에 요청된 실행은 차례로 처리하며, 같은 실행을 재시도하면 기존 버전과 릴리즈를 사용합니다.

릴리즈 버전은 빌드 중 EXE와 패키지 메타데이터에 적용하고 해당 소스 커밋에 태그를 생성합니다. `main`의 기준 버전 파일은 자동 커밋으로 변경하지 않습니다. 테스트가 실패한 실행은 릴리즈를 만들지 않으며, 게시 직전 오류가 발생하면 같은 실행을 다시 시도해 이어갈 수 있습니다.
