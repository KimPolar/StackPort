# StackPort

StackPort는 로컬 우선 원격 접속·데이터베이스 작업 공간을 만드는 프로젝트입니다. 전체 요구사항은 [기능 명세서](StackPort_Functional_Spec_KO.md)에 있습니다. 현재 코드는 초기 구현이며 명세 전체가 완성된 제품이 아닙니다.

## 현재 사용 가능한 기능

- Windows에서 PowerShell·CMD를 여러 로컬 터미널 탭으로 실행하고 크기 조절·종료 확인
- 각 터미널의 메모리 스크롤백에서 일반 문자열을 앞뒤로 검색하고 대소문자 구분
- Windows OpenSSH를 이용한 SSH 터미널과 호스트 키 지문 확인·고정·명시적 교체
- SSH 세션에서 개인 키 또는 에이전트에 등록된 공개 키 파일을 직접 선택
- SSH 연결 화면에서 DNS 조회와 TCP 포트 연결을 단계별로 진단
- 로컬 프로젝트 생성·이름 변경·복제·삭제와 프로젝트별 SQLite·SSH 연결 정의 저장 및 SSH 연결 수정
- 선택한 SSH 연결을 버전형 JSON으로 내보내고, 내용을 확인한 뒤 원하는 연결만 가져오기
- 기존 SQLite 파일에서 테이블과 뷰, 열·키·인덱스·생성 SQL을 읽기 전용으로 탐색
- 테이블과 뷰의 조건 필터, 다중 열 정렬, NULL 순서 설정 및 조회 SQL 확인
- 단일 읽기 전용 SQL 실행, 결과 100행씩 조회, NULL과 BLOB 구분 표시
- 필터·정렬 또는 SQL 매개변수가 적용된 전체 결과를 CSV로 내보내고 진행 행 수 확인·중단
- 실행 중인 SQLite 조회 중단과 시간 초과 표시, 중단 후 다시 조회
- SQL 매개변수를 감지해 텍스트·정수·실수·NULL·BLOB 값으로 바인딩
- SQLite 실행 계획을 단계별로 보고 인덱스 검색·스캔·임시 정렬 확인
- 지원되는 SQLite 테이블의 단일 셀을 미리보기·명시적 승인 후 변경하고 행 전체의 동시 수정과 저장 결과 검증
- 연결별 SQL 초안을 앱 실행 중 메모리에 보관하고, 프로젝트·연결 삭제 전 영향 확인
- SQLite 온라인 백업 API로 전체 DB 스냅샷을 만들고 무결성 검사. 기존 파일은 덮어쓰지 않음
- SQLite 백업의 대상·객체 수·행 수·SHA-256을 미리보고 새 파일로 복원해 검증
- 프로젝트·연결 변경, SQLite 셀 변경·백업·복원·CSV 내보내기의 로컬 작업 기록 조회

삭제 명령은 저장된 연결 정의만 삭제하며 데이터베이스 파일을 삭제하지 않습니다. 파일은 미리 존재해야 합니다. SQL 편집기는 읽기 전용으로, 하나의 결과를 반환하는 쿼리만 실행합니다. SQL 쓰기, DDL, PRAGMA 및 데이터베이스 첨부는 지원하지 않습니다. `SELECT :value`처럼 매개변수가 있는 쿼리를 실행하면 형식과 값을 입력하는 창이 열립니다. 입력한 값은 현재 조회와 페이지 이동에만 사용합니다. 조회에는 10초 시간 제한을 적용하며 중단이 확인된 뒤 결과를 표시합니다. SQLite가 긴 개별 작업이나 파일 잠금을 처리하는 동안에는 중단 확인이 지연될 수 있습니다. 셀의 긴 텍스트는 앞 4,096자만 표시합니다. 그리드의 필터와 정렬은 페이지 이동 중 유지되며 앱에 저장하지 않습니다. 직접 작성한 SQL의 결과 순서가 중요하면 `ORDER BY`를 지정하세요. 쿼리 초안은 앱 종료나 비정상 종료 후 복구되지 않습니다.

행 편집은 원본 SQLite 파일을 실제로 변경합니다. 기본 키가 있고 트리거·생성 열이 없는 일반 테이블에서 기본 키·고유 키가 아닌 짧은 텍스트, 정수, 실수 또는 NULL 셀 하나를 변경할 수 있습니다. BLOB, 긴 값, NULL/BLOB 기본 키와 가상 테이블은 편집할 수 없습니다. 미리보기 이후 행이 바뀌거나 제약·형식 검증이 실패하면 변경을 중단합니다. `PROD` 연결은 `PROD`를 직접 입력해야 합니다. 저장 후 자동 되돌리기는 없으므로 필요하면 먼저 백업하세요.

백업 및 복원 파일은 암호화되지 않으므로 저장 폴더의 권한으로 보호하세요. 백업 생성 뒤 탐색기의 **SQLite 백업 복원**에서 독립된 SQLite 백업을 선택하고 새 파일로 복원할 수 있습니다. 복원본을 별도로 열어 검사한 뒤 백업과 SHA-256이 일치할 때만 저장합니다. 예약, 암호화, 기존 데이터베이스 덮어쓰기와 자동 복원은 아직 제공하지 않습니다.

로컬 터미널은 Windows 10 1809 이상의 ConPTY가 필요합니다. PowerShell은 프로필을 불러오지 않고, CMD는 자동 실행 설정 없이 시작합니다. StackPort는 터미널 입력·출력을 저장하지 않지만 셸이나 실행한 프로그램은 자체 기록을 남길 수 있습니다. 여러 줄 붙여넣기와 터미널·앱 종료 시 확인하며, 터미널 종료 시 연결된 프로세스도 종료될 수 있습니다.

터미널의 `출력 찾기` 또는 `Ctrl+Shift+F`로 현재 탭의 화면과 메모리 스크롤백을 검색할 수 있습니다. 검색어는 탭에만 임시 보관하며 검색을 닫으면 지웁니다. 정규식과 디스크에 저장된 과거 출력 검색은 아직 제공하지 않습니다.

SSH는 Windows에 설치된 OpenSSH를 사용합니다. 처음 조회한 지문은 인증되지 않은 값이므로 서버 관리자에게 받은 값과 별도의 경로로 비교한 뒤 신뢰해야 합니다. 이후 저장된 키와 다른 서버는 차단되며, 키를 교체하려면 새 지문을 다시 확인하고 직접 승인해야 합니다. 프로젝트에 이름·호스트·포트·사용자와 환경을 저장할 수 있으며 저장된 `PROD` 연결은 열기 전에 `PROD`를 직접 입력해야 합니다. 직접 입력하는 임시 연결은 환경이 지정되지 않으므로 이 확인이 적용되지 않습니다. 연결 정의를 삭제해도 열린 세션과 호스트 키 신뢰 기록은 유지됩니다. 세션별로 자동, 지정한 키 파일(최대 8개), 암호 또는 서버 대화형 인증을 선택할 수 있습니다. 대화형 로그인에서는 서버의 안내와 확인 코드 질문에 터미널에서 답합니다. 키 파일 경로와 인증 응답은 저장하지 않습니다. 키 경로에 `%` 또는 `${...}`는 사용할 수 없습니다. 점프 호스트·터널·SFTP와 다른 OS의 SSH 지원은 아직 없습니다.

SSH 연결 화면의 DNS·TCP 진단은 서버에 짧은 TCP 연결을 시도하고 곧바로 닫습니다. SSH 호스트 키, 로그인 및 서버 권한은 검사하지 않으며 서버에 연결 기록이 남을 수 있습니다.

SSH 연결 가져오기·내보내기는 이름, 호스트, 포트, 사용자와 환경만 포함하며 암호·개인 키·호스트 키 신뢰 기록은 포함하지 않습니다. 파일에는 서버와 사용자 정보가 있으므로 공유 대상을 확인하세요. 가져올 내용은 미리 확인하고 선택해야 하며 같은 이름도 별도 연결로 추가됩니다. 파일 형식과 제한은 [구현 현황](docs/IMPLEMENTATION.md#ssh-연결-교환-형식)을 참고하세요.

다른 DB 엔진, 행 추가·삭제와 일괄 편집, 협업, AI, 브라우저 게이트웨이 및 설치·업데이트 패키지 등 나머지 기능은 아직 제공되지 않습니다. 브라우저에서는 로컬 파일 연결과 터미널을 제공하지 않습니다. 요구사항별 현재 상태는 [추적표](docs/requirements.csv), 구현 경계와 검증 범위는 [구현 현황](docs/IMPLEMENTATION.md)을 참고하세요.

## 개발 실행

Windows에서 Node.js 20.19 이상 또는 22.12 이상, Rust, C++ 빌드 도구, WebView2가 필요합니다. macOS와 Linux는 아직 검증하지 않았습니다.

```powershell
npm ci
npm run dev
```

다른 터미널에서 다음을 실행합니다.

```powershell
cargo run --manifest-path src-tauri/Cargo.toml
```

프런트엔드를 빌드하고 내장 리소스로 데스크톱 바이너리를 만들려면 다음을 실행합니다. 서명된 배포 패키지는 아직 구성하지 않았습니다.

```powershell
npm run build
cargo build --release --features custom-protocol --manifest-path src-tauri/Cargo.toml
```

메타데이터는 기본적으로 OS의 앱 데이터 디렉터리에 있는 `workspace.sqlite`에 저장됩니다. 별도의 위치를 사용하려면 실행 전에 `STACKPORT_DATA_DIR` 환경 변수를 지정할 수 있습니다. 버전 1·2 작업 공간은 이관 전에 같은 폴더에 무결성을 확인한 백업을 남깁니다. 연결 정의와 작업 기록이 포함된 폴더와 백업의 접근 권한은 사용자가 관리해야 합니다. 비밀번호나 개인키를 저장하는 기능은 없습니다.

```powershell
cargo test --manifest-path crates/stackport-core/Cargo.toml
npm run build
cargo check --manifest-path src-tauri/Cargo.toml
```

## Windows 자동 릴리즈

`main`에 커밋을 푸시하거나 GitHub의 **Actions → Windows build and release → Run workflow**를 실행하면 Windows x64 EXE를 빌드하고 GitHub Release를 하나 만듭니다. 빌드와 테스트가 성공해야 릴리즈가 게시됩니다. 실행 결과의 Actions 산출물과 릴리즈에는 `StackPort-Windows-x64.exe` 및 `SHA256SUMS.txt`가 포함됩니다. EXE에는 WebView2 Runtime이 필요하며 현재 코드 서명은 제공하지 않습니다.

버전은 `vMAJOR.MINOR.PATCH` 형식입니다. 첫 릴리즈는 소스의 기준 버전으로 시작합니다. 이후 `feat:` 또는 `feat(범위):` 커밋은 MINOR, `BREAKING CHANGE:` 또는 `!`가 붙은 Conventional Commit은 MAJOR를 올립니다. 그 밖의 변경이나 새 커밋이 없는 수동 실행은 PATCH를 올립니다. 수동 실행 시 `bump`를 `patch`, `minor`, `major`로 직접 선택할 수도 있습니다. 동시에 요청된 실행은 차례로 처리하며, 같은 실행을 재시도하면 기존 버전과 릴리즈를 사용합니다.

릴리즈 버전은 빌드 중 EXE와 패키지 메타데이터에 적용하고 해당 소스 커밋에 태그를 생성합니다. `main`의 기준 버전 파일은 자동 커밋으로 변경하지 않습니다. 테스트가 실패한 실행은 릴리즈를 만들지 않으며, 게시 직전 오류가 발생하면 같은 실행을 다시 시도해 이어갈 수 있습니다.
